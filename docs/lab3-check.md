# Проверка лабораторной №3

Это описание предыдущего этапа с демонстрационными данными. В текущей версии финансовые экраны требуют входа и работающего backend, а записи сохраняются в PostgreSQL. Порядок запуска и актуальные проверки см. в [README](../README.md) и [лабораторной №4](lab4-check.md). Состояния загрузки, ошибки и пустых данных по-прежнему проверяются браузерными тестами с управляемыми ответами финансового API.

## Запуск

Из корня проекта в PowerShell:

```powershell
npm.cmd ci
npm.cmd run dev
```

Откройте адрес из терминала, обычно `http://localhost:5173`. Для этой лабораторной достаточно frontend: демоданные доступны на `/demo/finance.json`. Установка backend описана отдельно в README.

## Пользовательские сценарии

1. Откройте обзор, измените месяц. Покажите итоги и пустой месяц, например январь 2020 года.
2. В операциях выберите тип, категорию и месяц; покажите пустой результат, затем сбросьте фильтры.
3. Откройте новую операцию и нажмите «Сохранить операцию» без заполнения. Покажите ошибки и фокус на поле суммы.
4. Введите сумму `0`, очистите дату, добавьте комментарий длиннее 200 символов. Исправьте ошибки: `1250,50`, расходная категория «Продукты», текущая дата и короткий комментарий.
5. Перед сохранением переключите тип на доход: категория очищается, список категорий меняется. Верните расход и выберите «Продукты».
6. Сохраните. Пока действие выполняется, поля и кнопка заблокированы. После сохранения операция появится в списке; обзор и бюджеты учитывают её сумму.
7. В бюджетах очистите месяц и введите отрицательный лимит. Покажите ошибки, затем выберите текущий месяц и сохраните `4000` для «Продукты». Появится подтверждение и, при превышении расходов, красный индикатор.
8. Измените месяц: подтверждение исчезнет, а лимит другого месяца будет независимым. Верните месяц и проверьте сохранённый лимит.
9. Покажите отмену формы, переходы назад/вперёд, прямой адрес `/budgets`, неизвестный адрес `/missing` и переключение темы. Обновление страницы сохраняет тему, но возвращает исходные операции и лимиты — это режим демонстрационных данных.

## Загрузка, ошибка и повторная попытка

В DevTools браузера откройте Network, отключите кеш и выберите медленную сеть. Обновите страницу операций: сначала отображаются подпись загрузки и скелетоны, затем записи.

В DevTools включите Offline и обновите страницу. Появится сообщение об ошибке и кнопка «Повторить загрузку». Перейдите в обзор, бюджеты или новую операцию: эти экраны тоже показывают ошибку, а меню и настройки продолжают работать. Верните сеть в Online и нажмите «Повторить загрузку»: появятся данные без перезагрузки страницы.

Для пустого месяца достаточно выбрать `2020-01`. Полностью пустой набор, ошибка сети и повреждённый JSON воспроизводятся автоматически в `e2e/dynamic.spec.ts` через перехват запроса JSON; исходный файл для этого не изменяется.

## Анимация и доступность

При переходе в другой раздел содержимое плавно появляется. Ошибки форм и подтверждение лимита раскрываются, индикаторы расходов обновляются с переходом. В DevTools, Rendering, задайте `prefers-reduced-motion: reduce`: анимация страниц отключится, переходы сократятся. Проверьте клавиатурой меню, формы и ссылку «Перейти к содержимому».

## Автоматические проверки

```powershell
npm.cmd run lint
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

Для последней команды нужен Microsoft Edge и свободный порт 4173. Браузерные тесты обновляют основные скриншоты и изображения загрузки, ошибки, пустых экранов, ошибок форм и сохранённого бюджета. Размеры — 1440 и 320 px. Скриншоты перечислены в README.

Проверки покрывают направление импортов между слоями, валидацию, суммы в копейках, относительные даты и формат JSON, общие данные между страницами, навигацию, состояния данных, повтор загрузки, блокировку сохранения и reduced motion.
