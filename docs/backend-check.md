# Проверка backend

Backend предоставляет API категорий, операций и месячных бюджетов. Данные
хранятся в PostgreSQL. React-интерфейс пока использует собственные демонстрационные
данные: результат запросов к API проверяется в Swagger UI или через HTTP.

## Запуск

Для уже настроенного проекта выполните из корня в PowerShell:

```powershell
cd backend
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Служба PostgreSQL должна работать. Откройте `http://127.0.0.1:8000/docs`.
Полная установка окружения, создание БД и настройка `.env` описаны в [README](../README.md).

## Что показать в коде

| Назначение | Файлы | Что происходит |
| --- | --- | --- |
| Создание приложения | `backend/app/main.py` | Подключаются маршруты и обработчики ошибок |
| Конфигурация | `backend/app/core/config.py`, `backend/.env.example` | Настройки читаются из окружения и локального `.env`; шаблон не содержит пароль |
| Подключение и сессии | `backend/app/db/session.py` | SQLAlchemy подключается к PostgreSQL через Psycopg и выдаёт сессию на запрос |
| Модели | `backend/app/models/finance.py` | Описаны таблицы, первичные и внешние ключи, уникальность и ограничения |
| Создание таблиц | `backend/migrations/versions/0001_finance_tables.py` | Alembic создаёт структуру БД; повторное применение не пересоздаёт таблицы |
| Формат запросов и ответов | `backend/app/schemas/` | Pydantic проверяет поля и формирует ответы |
| HTTP-маршруты | `backend/app/api/` | Обрабатываются GET, POST, PUT и DELETE |
| Бизнес-правила | `backend/app/services/` | Проверяются категории, связи и дубликаты, выполняется `commit()` |
| Автоматические проверки | `backend/tests/`, `backend/scripts/check_api.py` | Проверяются ошибки, CRUD, ограничения и сохранение данных после перезапуска |

Путь запроса: маршрут → схема валидации → сервис → сессия SQLAlchemy → PostgreSQL.
Ответ проходит через схему ответа и возвращается JSON. При ошибке валидации
сервис не вызывается. При ошибке записи незавершённая транзакция откатывается
при закрытии сессии.

В каждой таблице UUID — первичный ключ. `category_id` связывает операции и бюджеты
с категорией. Суммы хранятся целыми копейками, поэтому 125050 — это 1 250,50 ₽.
Тип операции определяется категорией. Бюджет имеет уникальную пару категории
и месяца, а его составной внешний ключ допускает только расходную категорию.

## Сценарий демонстрации

В Swagger UI выберите маршрут, нажмите **Try it out**, заполните параметры и
нажмите **Execute**. Для разных запусков используйте новое имя категории либо
удаляйте ранее созданные записи в конце сценария.

1. Вызовите `GET /api/health` и `GET /api/health/db`: оба возвращают 200 и
   `{"status":"ok"}`. Первый проверяет приложение, второй — подключение к БД.
2. Создайте категорию через `POST /api/categories`:

```json
{"name": "Продукты для проверки", "type": "expense"}
```

Ожидается 201. Скопируйте UUID категории из ответа.

3. Создайте операцию через `POST /api/transactions`, заменив строку-заглушку UUID:

```json
{
  "category_id": "UUID_КАТЕГОРИИ",
  "amount_kopecks": 125050,
  "date": "2026-09-25",
  "comment": "Проверка сохранения"
}
```

Ожидается 201. Скопируйте UUID операции.

4. Создайте бюджет через `POST /api/budgets`:

```json
{
  "category_id": "UUID_КАТЕГОРИИ",
  "month": "2026-09-01",
  "limit_kopecks": 500000
}
```

Ожидается 201. Скопируйте UUID бюджета. Бюджет — лимит на месяц, поэтому дата
месяца всегда указывает первое число.

5. Покажите GET по UUID и списки с фильтром `category_id`. Для бюджета добавьте
   `month=2026-09-01`, для операций — `date_from=2026-09-01` и `date_to=2026-09-30`.
6. Остановите Uvicorn через Ctrl+C, запустите той же командой и повторите GET
   по сохранённым UUID. Записи остаются в PostgreSQL.
7. Через PUT измените название категории, сумму операции и лимит бюджета.
   Передавайте все обязательные поля. В ответе ожидается 200, повторный GET
   должен показать новые значения.
8. Покажите обработку ошибок по таблице ниже.
9. Удалите бюджет и операцию, затем категорию. DELETE возвращает 204 с пустым
   телом, последующий GET удалённой записи — 404.

## Ошибки для демонстрации

| Действие | Статус | Причина |
| --- | --- | --- |
| Передать сумму операции 0 | 422 | Сумма должна быть положительной |
| Передать `month` как `2026-09-02` | 422 | Месяц бюджета должен начинаться с первого числа |
| Создать бюджет для доходной категории | 422 | Лимиты относятся к расходам |
| Повторить POST бюджета той же категории и месяца | 409 | Такой бюджет уже существует |
| Удалить категорию с операциями или бюджетами | 409 | Сохраняется целостность связей |
| Изменить тип категории с операциями или бюджетами | 409 | Нельзя переопределять тип связанных записей |
| Запросить удалённую запись по её UUID | 404 | Запись отсутствует |
| Передать `wrong` вместо UUID | 422 | Неверный формат идентификатора |

Ошибка не должна изменять ранее сохранённые данные. Это можно показать повторным
GET после неудачного PUT. Поле `detail` содержит описание ошибки; для ошибок
валидации — список с указанием полей.

## Автоматическая проверка

Из папки `backend`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m scripts.check_api
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic check
```

`unittest` использует PostgreSQL, но откатывает данные каждого теста.
`scripts.check_api` проверяет настоящие HTTP-запросы и сохранение после перезапусков:
записывает временные данные, затем удаляет их. Ожидаются сообщения `PASS` и код
завершения 0. При ошибке команда завершается с ненулевым кодом.

- Сценарий с Uvicorn подтвердил создание, сохранение, изменение, фильтрацию
  и удаление всех трёх сущностей; данные и изменения пережили перезапуски.

- Создание всех таблиц проверено в отдельной пустой временной схеме PostgreSQL.
  Схема удалена после проверки; рабочие таблицы не пересоздавались.
- `pip check` не обнаружил конфликтов зависимостей.
- Frontend: lint, четыре теста логики и сборка прошли. Vite сообщил
  предупреждение о JavaScript-файле размером более 500 kB; сборка завершилась успешно.
