## Запуск настроенного проекта

PostgreSQL должен работать. Первоначальная установка зависимостей и настройка БД описаны в [README](../README.md).

Первый терминал PowerShell, из корня проекта:

```powershell
cd backend
.\.venv\Scripts\python.exe -m scripts.configure_auth
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Второй терминал, из корня проекта:

```powershell
npm.cmd run dev
```

Откройте `http://localhost:5173`, зарегистрируйтесь или войдите в существующий аккаунт. Если порт занят, Vite покажет выбранный адрес. API: `http://127.0.0.1:8000/docs`; проверка БД: `http://127.0.0.1:8000/api/health/db`. Остановка каждого сервера — Ctrl+C. JWT-ключ и пароль БД находятся только в локальном `backend/.env`; существующий ключ сохраняется.

## Форматы и обновление интерфейса

| Сущность | POST / PUT | Успешный ответ | Обновление UI |
| --- | --- | --- | --- |
| Категория | `{name, type}`, тип `expense` или `income`, имя от 1 до 80 символов | `{id, name, type}` | Категория появляется в списке и формах. При переименовании обновляются названия в операциях, бюджетах и обзоре |
| Операция | `{category_id, amount_kopecks, date, comment}` | Те же поля и `id`; дата `YYYY-MM-DD` | Тип и название определяются категорией. Создание, редактирование и удаление пересчитывают итоги и расходы по бюджетам |
| Бюджет | `{category_id, month, limit_kopecks}`, месяц `YYYY-MM-01` | Те же поля и `id` | Сохранение создаёт или заменяет лимит категории в выбранном месяце; удаление снимает только этот лимит |

Операции: `/api/transactions`, редактирование и удаление — `/api/transactions/{id}`. Аналогично устроены `/api/categories` и `/api/budgets`. Удаление возвращает 204 без тела; интерфейс удаляет запись только после успешного ответа. POST возвращает 201, PUT — 200. Для изменения бюджетного лимита используется UUID существующего бюджета, для нового — POST. Конфликт создания лимита из другой вкладки обрабатывается чтением существующего бюджета и его обновлением.

Суммы формы переводятся из рублей в целые копейки; предел — 99 999 999 999 копеек. Комментарий ограничен 200 символами. Все списки читаются страницами `limit=100&offset=...`, пока не будет получена последняя страница. Проверено 107 операций и корректный итог по 101 записи одного месяца.

Финансовые запросы передают Bearer access token. Refresh хранится в HttpOnly cookie; параллельные 401 в приложении используют одно обновление сессии. Права проверяются на сервере по владельцу категории; чужие UUID возвращают 404. По прямому адресу редактирования чужой или удалённой операции форма недоступна.

При 409 от сервера интерфейс показывает причину: дубликат, связанная категория или запрещённая смена типа. При 422 показывается сообщение о неверных данных. Сетевая ошибка оставляет введённые поля и запись на месте; запрос можно повторить. Удаление или смена типа категории со связанными операциями либо бюджетами запрещены сервером. Для бюджета интерфейс меняет лимит выбранной категории и месяца; перенос бюджета доступен через API.

## Демонстрация MVP

1. Откройте `/transactions` без входа: приложение предложит авторизоваться. Зарегистрируйте новый аккаунт. В нём нет операций и лимитов; начальные категории уже созданы.
2. На вкладке «Категории» создайте расходную категорию «Учёба». В «Новой операции» выберите её, задайте 1 000 ₽, текущую дату и комментарий «Проверка лабораторной №5». Сохраните. Запись появится в списке.
3. Откройте обзор текущего месяца: расходы увеличились на 1 000 ₽. В бюджетах выберите «Учёба» и сохраните лимит 1 500 ₽. Остаток — 500 ₽. Обновите страницу: данные сохранятся.
4. В списке операций нажмите «Редактировать», укажите 2 000 ₽ и сохраните. В обзоре сумма изменится, в бюджете появится превышение на 500 ₽. Измените дату на другой месяц: расход перейдёт в итог этого месяца.
5. Переименуйте категорию «Учёба» в «Обучение». Проверьте новое название в операции и бюджете. Попытка сменить её тип или удалить её покажет сообщение о связанных записях.
6. Верните дату операции в текущий месяц. Нажмите «Удалить операцию» и сначала отмените: запись останется. Подтвердите повторное удаление: запись исчезнет, итоги и расходы бюджетов пересчитаются. Обновление страницы не восстановит её.
7. В бюджетах удалите лимит «Обучение»: исчезнет только лимит выбранного месяца. Затем удалите свободную категорию. Список и формы обновятся.
8. Выйдите и войдите снова: собственные данные восстановятся. В другом профиле браузера создайте второй аккаунт: он не видит записи первого. Прямой адрес редактирования операции другого пользователя показывает «Операция недоступна».
9. Проверьте интерфейс на ширине 320 px и переключение темы. Русские календари выбора месяца работают в обзоре и бюджетах.

## Результаты проверок

Проверено 7 октября 2026 года:

| Команда | Результат |
| --- | --- |
| `npm.cmd run build` | TypeScript и сборка Vite проходят |
| `npm.cmd run lint` | Без ошибок |
| `npm.cmd test` | 12 тестов проходят |
| `npm.cmd run test:e2e` | 19 сценариев проходят; обновлены 48 скриншотов |
| `python -m unittest discover -s tests -v` из `backend` | 40 тестов проходят |
| `python -m scripts.check_api` из `backend` | CRUD, валидация и сохранение после двух перезапусков проходят; временные записи удалены |
| `python -m alembic current` / `python -m alembic check` | Версия `0002 (head)`, новых операций миграции нет |
| `python -m pip check` | Конфликтов зависимостей нет |

Для команд backend используется `backend/.venv/Scripts/python.exe`. Установка тестовых зависимостей при первой настройке: `python -m pip install -r requirements-dev.txt` из `backend`.

Браузерная обёртка запускает собственные API и Vite на свободных портах и создаёт случайную временную схему PostgreSQL. Проверяет её миграции и доступность БД, затем запускает Playwright с Microsoft Edge. После завершения останавливает свои серверы и удаляет только созданную схему. Access token тестового API действует 2 секунды. Серверные тесты откатывают транзакции; рабочие данные не заменяются демонстрационными.

CRUD, права владельцев, пустые данные нового аккаунта и сохранение проверяются с реальными запросами. Для воспроизводимой проверки отображения ошибок отдельные сценарии имитируют сетевой отказ, 403 и 422, не подменяя успешные сценарии CRUD. Тесты загрузки также задерживают реальные запросы.

Vite сообщает о размере основного JS-файла больше 500 kB; это предупреждение сборки, TypeScript и сборка завершаются успешно.

## Основные файлы

- `src/entities/finance/api/api-repository.ts` — запросы CRUD, сопоставление UUID, чтение всех страниц и обновление данных из ответов сервера.

- `src/pages/TransactionsPage.tsx`, `src/pages/BudgetsPage.tsx`, `src/shared/ui/DeleteButton.tsx` — действия удаления и подтверждения.
